The production application offers explicit separation models from the server catalog. Adaptive output and server Auto are disabled in production and DEV. The browser exposes Auto only when the server advertises an enabled authoritative or adaptive route; a stale saved Auto choice resolves to an available catalog choice.

The retired Auto implementation ranked fixed Demucs outputs by energy. This measured neither instrument identity nor separation quality. On “Tab Steps Out,” the six-source output had a shared end transient and quiet musical content. A forced two-part retry restored level but put trumpet into the model’s vocals output. This failed the intended musical behavior, so the forced retry has been removed.

The experimental adaptive implementation remains behind its existing flags for evaluation. Its concentrated-energy quality check ends a failed operation and releases the user allowance; it does not select another model. Previously accepted alternate attempts retain their original contract so deployment can finish existing work safely. Completed saved runs and their audio remain untouched.

The optional `REPLICATE_FALLBACK_API_TOKEN` handles provider availability independently of musical selection. Separation and video-import starts try it only after HTTP 401, 402, 403, or 429. An unknown result, timeout, server error, malformed success, or redirect preserves the original attempt for reconciliation. Polling and cancellation locate the same prediction with either configured credential. The model, source, webhook, owner and allowance remain unchanged. Auto requires reviewed real recordings, instrument-confusion checks, and useful separation before returning to production. Passing codec, transport, queue, or synthetic signal tests alone cannot establish those properties.
