# Current authority across Stem Splitter

The user's requested audit covers a guest, an SSO-authenticated CAIL individual
without a class, a recognized enrolled student, and an instructor who can use
the console. Identity, general Lab membership, class assignment and application
administration are distinct. Each existing server boundary remains authoritative.

Navigation and controls must follow current capabilities, including role loss
and recovery in an already open page. Optional class discovery must not strand
an individual user's Personal workspace. Paginated class discovery must reach
later assignments and stop on a nonadvancing or excessively long response.

Workspace rechecks the exact selected class before displaying its controls and
on refresh. A changed role clears the previous role's roster, conversations
and drafts before loading the newly authorized view; unchanged grants preserve
drafts, loaded pages and scroll. A denied or uncertain class lookup conceals
class data while Personal remains independently available.

Application instructor folders recheck on focus and tab return. Uncertainty
conceals the tools without discarding drafts. Revocation clears the tools and
fences late reads. No role, permission, credential, database schema or provider
setting is expanded. Real sign-ins and paid model/separator calls are outside
the automated audit; existing signed-in Firefox activity remains untouched.
