# Workspace controls

User screenshots identify mismatched browser-native workspace menus, a moving
account control, unwanted Guest text, class actions hidden in separate views,
verbose refresh copy, and a Resplit default of four with six offered.

Use the existing Stem typefaces, colors, borders, touch targets and focus rings.
Keep the login and logout control in one consistent header slot, remove the
Guest separator and retain normal sign-in/sign-out destinations. A custom menu
backed by the existing select must support pointer and keyboard choices,
typeahead, Escape, Tab, current selection, disabled state and narrow screens.
Server course authorization continues to determine available choices.

Create shared split stays available across class sections and preserves the
selected course and existing disclosure. Make class folder opens the existing
folder creation workflow. Instructor-only creation remains until the requested
participant-creation policy is confirmed; a visible action cannot grant roles.
Show only the last update time, aligned with Refresh at the right.

Resplit defaults to the available two-stem option and offers only two/four-stem
models from the server catalogue. Original upload choices and stored jobs keep
their contracts. Model, workspace and placement remain independent choices.

Release as local reviewed commits through Dev-first exact-source gates, then
production and the pending coordinated Doorway change. Browser-local state
migration has a separate privacy and conflict review; no origin-wide storage
copy, implicit personal-to-class move or destructive draft replacement.
